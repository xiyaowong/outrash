# outrash

扫描本机开发工具的缓存目录，列出可以重新下载或重新编译的内容。默认只勾选可以安全清理的项，你在列表上调整后按“开始清理”。

![界面概览](testdata/shots/overview.png)

## 安全约定

- 列表本身就是计划：勾选的项就是会被删除的路径，界面上没有第二处清单。
- 只有扫描时量到的、位于 `internal/core/rules.json` 缓存根之下的路径才可能被勾选，且不能等于缓存根本身。
- 盘符根和盘符下一级目录一律拒绝，计划项本身是符号链接时也拒绝（扫描不跟随链接）；主目录本身不会被列为计划项。
- 列表里只出现各工具能自行重新下载或重新编译的内容。
- 不写配置、注册表、日志或历史；除删除动作本身外没有任何持久化。

## 构建与运行

```sh
just debug       # 不删除：按“查看清理计划”列出路径、大小和顺序，同时打印到 stdout
just safe        # 正常界面，但拒绝执行任何删除
go run .         # 打开窗口，扫描后按工具分组显示
```

`-debug` 隐含 `-no-delete`。`just ci` 跑 build、vet 和测试。

## 添加一个缓存

规则都在 `internal/core/rules.json`，通过 `go:embed` 在构建时打包。在分组里加一个 item：`id`、`name` 必填；`env` 是优先读取的环境变量；`paths` 按 `windows`/`darwin`/`linux` 给出路径模板，支持 `~` 和 `%VAR%`；`unit` 为 `entries`（默认，根的每个子项算一项）或 `versioned`（根/包/版本，可执行“保留最新”）；`exclude` 列出根下同住但**不可重建**的子目录（如 Poetry 的 `virtualenvs`），它们既不进列表也不计入大小。可选的 `probe` 会在环境变量未设置且默认路径都不存在时调用工具查询自己的缓存位置。
